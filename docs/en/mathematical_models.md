# Mathematical model graphs

Schema `"0.5"` records **quantities**, **relationships**, and **their assembly
into a model**. The existing Equation remains the source of mathematical text.
A model explicitly connects its relations through shared quantities. Recording
one relationship is useful even when it cannot determine a solution on its own.

## What is recorded

| Record | Meaning |
| --- | --- |
| `QuantityDefinition` | A revisioned quantity meaning, LaTeX spelling, unit, domain and coordinate references. This differs from a Context's numeric `{value, unit}` datum. |
| `Equation` | A relationship's mathematical text, local symbols, scope, assumptions and sources. This remains unchanged from v0.3. |
| `MathematicalModel` | Selected relation instances and their explicit symbol-to-quantity connections. This differs from the existing Model's registration metadata. |
| Nested `ModelQuantity` | A local alias for one QuantityDefinition revision and its role in this model: `coordinate`, `input`, `parameter`, `unknown`, or `derived`. |
| Nested `RelationInstance` | An Equation revision, a role such as boundary condition or likelihood, a `kind`, and a complete local-symbol mapping. |

Relation kinds are `equation`, `constraint`, `distribution`, and `optimization`.
The kind describes the adopted statement; it does not parse or execute it.
Boundary conditions, closure choices, priors and likelihoods are distinguishable
through the relation's authored role and Equation scope. Unknown and input roles
belong to the model: a temperature may be solved in one model and supplied in another.

IDs are local to a contract. Every definition reference includes its revision.
Within a model, a QuantityDefinition revision has one alias. Sharing that alias
means sharing the declared quantity; equal symbols or equal units alone do not.
Different atmospheric regions, gas and total pressure, and gas temperature and
an effective pressure temperature need distinct definitions when their meanings
differ. A conversion or average is another relation, not an implicit alias.

For example, these two relation instances share gas pressure and density:

```yaml
relations:
  - id: eos
    equation: {id: ideal_gas, revision: '1'}
    role: State equation
    quantities: {P: pressure, rho: density, R: gas_constant, T: temperature, z: height}
  - id: balance
    equation: {id: hydrostatic_balance, revision: '1'}
    role: Mechanical balance
    quantities: {P: pressure, rho: density, z: height, g: gravity}
```

This excerpt omits the quantity definitions and the model's alias declarations.
The complete [isothermal example](../../examples/mathematical_models/isothermal.yaml)
also adopts a uniform temperature and a lower pressure boundary. Its four
relations are the ideal-gas law, hydrostatic balance, `T(z)=T0`, and `P(0)=P0`.
The analytic implementation is declared separately; its correspondence
Assessment intentionally remains **unknown**.

The same Equation can occur in several instances with different connections.
Instances are the initial reusable building blocks; no separate component
library, numerical solver or automatic closure inference is required.

## Inspect a model

```bash
mceg model examples/mathematical_models/isothermal.yaml \
  --model atmosphere --format json
mceg model examples/mathematical_models/isothermal.yaml \
  --model atmosphere --format mermaid --output /tmp/atmosphere.mmd
mceg model examples/mathematical_models/isothermal.yaml \
  --model atmosphere --format tex \
  --output examples/mathematical_models/model_definition.tex
```

Use `--revision` when an ID has more than one revision. Omitting it never selects
a newest revision implicitly. `--check --output PATH` compares generated bytes
without changing the artifact or renewing any Assessment pins.

The JSON uses format `mceg_mathematical_graph_v1`. It contains quantity-alias and
relation-instance nodes, undirected incidence edges labeled by local symbols,
the definition records, model scope and the model dependency digest. Coordinate
references remain in the quantity definitions. This is a mathematical view,
separate from the assurance-oriented `mceg graph` format and viewer interface.

```{graphviz}
graph atmosphere {
    rankdir=LR;
    node [shape=ellipse];
    P [label="Gas pressure"];
    D [label="Mass density"];
    T [label="Gas temperature"];
    node [shape=box];
    E [label="State equation"];
    H [label="Hydrostatic balance"];
    I [label="Isothermal closure"];
    B [label="Pressure boundary"];
    E -- P; E -- D; E -- T;
    H -- P; H -- D;
    I -- T; B -- P;
}
```

This abridged diagram omits supplied constants and the coordinate. An edge means
that a quantity occurs in a relation, not that a function produces it. Coupled
cycles are allowed; only coordinate-definition dependencies must be acyclic.
The model need not be a computational DAG or a complete solvable problem.

## Connect the definition to verification

Claims can reference `mathematical_models: [{id: atmosphere, revision: '1'}]`.
Their support Assessments can pin those definitions with
`mathematical_model_pins: [{id: atmosphere, revision: '1', sha256: ...}]`.
Supported and contradicted Assessments must pin every referenced model.

`mathematical_model_digest(contract, model_id, revision)` includes the model,
its connection maps and roles, referenced Equation revisions, and referenced
QuantityDefinition revisions with their coordinate dependencies. A changed
meaning or connection therefore makes an old pin stale even if equation text
is unchanged. Claim/Assessment dependencies also carry these records into
Decision and Use checks. An old review remains readable; a mismatch never
rewrites its scientific status or implies a new execution.

EquationBindings still declare code correspondence. A numerical implementation
of a coupled system may have several bindings to one function. Static checks
can inspect recorded declarations; evidence must separately establish that the
implementation uses the intended quantities and coupling. For example, a
radiation-feedback Claim can combine graph-path inspection with a numerical
test of whether changed opacity affects the field and the excitation rates.
Make that scoped Assessment a required Use item when feedback is essential.

To pin an EquationBinding, also list its Equation explicitly in the Claim's
`equations` and the Assessment's `equation_pins`, as in v0.3. A model reference
does not select code bindings implicitly.

Definitions themselves have no `supported` status. A graph does not discover
all missing physics, prove independence of equations, show that enough boundary
conditions were supplied, establish existence or uniqueness, or prove code
equivalence. Equal units do not establish physical identity. Structural unit
checks compare the explicitly declared strings exactly; there is no dimensional
algebra or automatic conversion. Domain prose records the intended meaning; it
is not a machine-interpreted compatibility predicate.

## Keep documentation and runtime separate

The TeX export lists the selected model's quantity meanings, roles, coordinates,
adopted equations and explicit mappings. Include the generated fragment in a
provider-owned document, then compile and visually inspect it. An export never
executes TeX or arbitrary code; authored math is retained as TeX rather than
validated as a safe or machine-interpreted language.

```bash
mceg model examples/mathematical_models/isothermal.yaml --model atmosphere \
  --format tex --output examples/mathematical_models/model_definition.tex --check
cd examples/mathematical_models
pdflatex -no-shell-escape -interaction=nonstopmode -halt-on-error \
  -output-directory=/tmp model.tex
```

Providers need MCEG only when authoring or checking these records. Their runtime
code need not import or depend on it. SymPy, general dimensional analysis,
solver generation and cross-contract component composition are outside this
first implementation.

Earlier schemas and Equation digests retain their behavior. Existing symbol
tables may be incomplete or group several symbols into one entry, so migration
is explicit: author precise definitions and mappings rather than automatically
promoting every old symbol to a shared quantity.
