# 実験的v0.1の基準点

2026-10-15に最初の概念実証を固定します。パッケージ版は`0.1.0`、Gitタグは
`v0.1.0`、契約ファイルの版は`schema_version: "0.1"`です。
再現可能な開発の基準点であり、最終的な科学標準ではありません。

## 固定する範囲

- [スキーマ仕様](../en/schema.md)と[schema.py](../../src/mceg/schema.py)が定める
  YAMLのフィールド、型、必須・任意の項目、列挙値。
- 適用領域、主張、テスト結果、確認状況、照合結果の各状態の意味。
  `documented`や`supported`は、証拠を記録した宣言を表します。
- ローカル参照、重複キー、証拠の種類、出典リンクの循環などに関する構造検査。
- 公開する`Contract`、`load_contract`、`trace_provenance`、CLIの検査・追跡動作、
  終了コード、追跡レポートのフィールド。人向けのエラー文面は固定対象に含めません。

`recorded_audit_complete`は、追跡対象について、記録された資料の確認と一次資料までの
整合した照合が完了していると宣言されていることを意味します。科学的妥当性、依存情報の
網羅性、独立した再現、計算への適用可能性を保証しません。この区別も、
[出典追跡](provenance.md)に記載した固定対象の意味に含まれます。

## 固定後の変更方針

`v0.1.0`タグは変更しないスナップショットです。後の訂正は新しいコミット・版に
記録し、訂正を取り込む目的でタグを移動しません。

パッケージ版`0.1.x`では、固定したスキーマと意味に沿った実装の修正や説明の改善を
行えます。以前に誤って受理・拒否していた入力の修正を含め、検査結果が変わる場合は
変更履歴に記録します。`schema_version: "0.1"`のままフィールドや列挙値を追加したり、
状態の意味を変えたりはしません。

スキーマの拡張は`"0.2"`以降で行い、移行方法を明記します。v0.1のValidatorは
未知のフィールドを拒否するため、任意のフィールドでも、追加して記述すると旧版では
読み込めません。「任意項目だから互換性がある」とは判断しません。

科学的な契約内容や監査結果は、スキーマを変えずに更新できます。以前の状態をGitに
残し、確認した資料と対象範囲、結論を変更した理由を記録します。不明な情報は不明の
ままでも構いません。未取得の原論文を入手することは、今回の固定の前提条件ではありません。

5件の契約例、H₂ケース、保存した実行記録もタグのスナップショットに含めます。
ケースと実行記録は例専用の形式であり、汎用のMCEGスキーマではありません。
ハッシュ対象の入力やソースを変更した場合は、例を再実行して対応する記録を作ります。
ハッシュだけを書き換えて、再実行したように見せることはしません。

## 次版以降に残すこと

適用条件の構造化、証拠間の関係の種類、単位を理解した照合、外挿の自動判定、
契約をまたぐ推論、グラフデータベースはv0.1の対象外です。
[設計課題](design_questions.md)と[部分的な一次資料監査](h2_primary_audit.md)に、
その理由と残された証拠不足を記録しています。
パッケージの変更は[変更履歴](../../CHANGELOG.md)に記載します。
